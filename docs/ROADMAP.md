# 产品路线图与版本划分

## 北极星目标

Agent 接到一个禅道 Bug 后，自动查询可信研发上下文，定位候选代码，获得正确的构建与部署服务关联，并在人工许可下完成交付；对任何不确定或过期关系都能给出证据和阻断理由。

## 版本安排

| 版本 | 交付价值 | 必须达成 | 禁止偷跑 |
|---|---|---|---|
| V1.0 — Discover & Catalog | 一次初始化，长期复用可信服务目录 | 三 Adapter 只读、源码/构建/部署解析、AI 候选、人工审核、CLI/MCP、离线测试 | 构建/部署等外部写操作 |
| V1.1 — Agent Context | Cursor/Codex/Grok Bot 快速获取具体 Bug 上下文 | 图片、安全摘要、查询缓存、质量评测、MCP 真实接入 | 未授权代码修改 |
| V1.2 — Build Workflow | 代码修复以后 GitLab 构建可跟踪 | 分支/MR/CI 计划、Build/Artifact/SHA 绑定、失败诊断、审批与审计 | 跳过代码审核或允许生产部署 |
| V2.0 — Test Release Loop | 正确环境的测试发布 + 回归 + 禅道回写 | 发布计划、Swarm 预检、可回滚、健康检查、回写凭证与状态 | 无审批生产发布、批量重部署 |
| V2.1+ — Collaborative Agent | 多角色任务分发、长期同步、跨系统消息 | 任务状态机、幂等恢复、团队权限与观测 | 替代现有企业运维权限体系 |

## 最小可用版本判断

- V1.0 结束时，系统应能从合成数据自动检测 3 Stack 中的过期集群关系、71/78 配置漂移和镜像复用，并为合成 Bug 返回截图资源与候选模块。
- V1.1 结束时，用户应在本机用 Cursor 直接调用 MCP 读取 BugContext（前提是用户明确授权连接真实内网）。
- V1.2 结束时，**构建是调用已授权 GitLab CI，不能在 Agent 电脑上随意运行任意生产 build 脚本**。
- V2.0 结束时，部署需要明确目标：项目 + 模块 + 镜像 digest + Stack + Endpoint + Swarm + Service + 环境；若任何关键映射未确认，发布应失败并给出待审核项。

## 验收产品指标（建议，不作为既定事实）

- 工具调用压缩：对一个 Bug 的基础上下文获取由多轮浏览器点击缩减到一次 `bug_context` 调用；记录工具调用数和输入 token 用于对比。
- 关联正确性：无证据的语义关系绝不直接变为 confirmed；误把历史 Stack 当可部署目标的数量必须为 0。
- 可靠性：模拟同一资源重复扫描多次仍无重复、审核历史不丢、断点续跑成立。
- 可解释性：每个映射候选可以显示至少一个 evidence，且版本可追踪。
